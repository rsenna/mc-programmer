In electronic musical instruments manufactured by
Roland, every single parameter which you can read
or modify using system exclusive messages has its
own unique address. This way we can unambiguously
refer to each parameter. Thanks to the address,
the instrument knows what we would like to read
or modify. The range of addresses is limited and
not every address has its own assigned value.
Some of the addresses may be empty. Some of them
contain data which may not be interesting for us
in this particular context of sound design but can
be interesting for some other things. And finally,
some of the addresses contain information about
the ZEN-Core synth patches. Such a concept of
assignment of values or parameters to addresses
creates something like an address space or a
memory map known from microprocessor systems. In
other Roland's musical instruments documentation,
I noticed that their address spaces are specific
to the particular instrument, but luckily for us,
they have many common features also with the MC
grooveboxes. The ZEN-Core sound parameters or the
ZEN-Core patches are stored in specific data
structures across the instrument's parameters
memory map. It's not an official name, but in
this video, I will refer to them as ZEN-Core
tone descriptors or ZEN-Core sound descriptors.
In MC-101 and MC-707, the huge block of the
ZEN-Core tone descriptors start at the address of
three and 70 hexadecimal. In other Roland musical
instruments, the addresses and the organization
of the ZEN-Core sound descriptors are different.
In this diagram, you can see the starting
addresses of the descriptor blocks in MC-707. As
you can see, each track has 17 descriptors. Roland
MC-101 and MC-707 really have a lot of ZEN-Core
descriptors for tone tracks because each tone
clip and each tone track has its own descriptor.
This results in 128 descriptors for just the clip
sounds plus one separate descriptor for each track
tone. An interesting compatibility thing is that
MC-101 has the same descriptor set as MC-707,
but in 101 you can play sound only from the
descriptors for tracks number one to four.
If you initialize a track as the tone track, only
one of the 17 descriptors will be loaded to the
ZEN-Core sound synthesizer of that track.
If you choose track as the sound source,
the track tone descriptor will be loaded to
the track sound synthesizer. And if you choose
clip as the sound source, one of the clip sound
descriptors will be loaded at a given time. The
other descriptors will be ready to be loaded
immediately after you select another clip.

Now let's see how to read and modify them. We
can imagine a MIDI system exclusive message as an
empty box. A box that doesn't contain any useful
information, but we can put some data in it. gear
manufacturers decide what to put in that box or
in other words what data to put there and how the
data should be ordered or we can say structured.
Two of the commonly used types of packets that
we can put inside the SysEx messages for Roland
instruments are data request one and data set one
or DT1. Data request one allows us to read the
internal parameters of the Roland instrument.
And if you want to write the internal parameter
to the Roland instrument, you may want to use the
data set message or DT1. The DT1 message is also
the response message to the data request message.
Fortunately, Roland MC-101 and MC-707 use these
messages too, and you can find information about
them in Roland's MIDI implementation charts
of a few other instruments. This diagram shows
the system exclusive message for requesting data
from a Roland instrument that supports the SysEx
communication. It is basically a SysEx message
but with a specific data structure inside it.
We need to provide the model identification number
in the message in bytes 3 to 6. It's just a series
of numbers three bytes and 5D or 5E hexadecimal
whether we communicate with MC-707 or MC-101. The
field that distinguishes the data request message
is at the index 7 and its value is 11 hexadecimal.
The address will tell the instrument from which
internal location you would like to read the
data. The length field tells the instrument how
many bytes of data you'd like to read. Please
remember that the length field is very poorly
supported in my software. It doesn't allow you
to encode any values larger than 127. But I
just don't think there is a need to implement
such large reads. So I just left it this way.
The instrument will return the data starting
from the given address and will continue reading
towards the higher addresses. The maximum number
of returned bytes will be up to length. But
if there is an empty location before the end
of the requested length is reached, the MC-707 or
MC-101 will just return less data. As a response,
you will get the data set or DT1 message. You
can also use the DT1 message to set the internal
parameters of the Roland instrument. DT message
structure is shown here on the screen. Here the
byte that allows the instrument to distinguish
the message is 12 hexadecimal at index 7. And
again you specify the address to write the data
but this time you specify explicitly the data
that you want to write. Each next byte of data
fields will be written at the next higher address.
Both the request and the data set packets use a
checksum byte. This byte contains a number which
depends on the values of bytes from index 8 onward
up to the checksum. For example, we take data from
bytes of index 8 to 15 for the request message.
